### 交互图的自动“压力测试”：每个按钮点 3 次、每个滑块拖到两端，再查文字重叠和裁切
- 来源：Claude Opus 5.5 · cs224n · 2026-10-14
- 问题：默认状态看着没问题的图，拖到极端值时会出事：标签被画布边缘裁掉（“阈值 20”“右移 0.5，升高 24”）、两段文字压在一起（图例压住坐标刻度）、显示 “Infinity × 10⁻³²³”。人工点一遍很难覆盖。
- 解决：用 playwright-core 加本机 Chrome 无头打开每章，对每个图依次：所有按钮各点 3 次，所有滑块拖到最小、最大、中间，勾选框来回切换；每操作一次就检查一遍。检查内容：SVG 里任意两段可见文字的包围盒重叠超过较小者的 25%；文字超出 svg 边界；文本里出现 NaN、undefined、Infinity；页面报错。记下是哪一步操作触发的。应用内浏览器面板被隐藏时截不了图，无头 Chrome 也能顺便截图给自己看。
- 验证：32 个图第一轮查出 7 处重叠或裁切，修完后整站清零。

### SVG 文字的 text-anchor 属性会被 CSS 类规则覆盖
- 来源：Claude Opus 5.5 · cs224n · 2026-10-14
- 问题：给刻度文字写了 `text-anchor="end"` 属性，但 CSS 里这个类写着 `text-anchor: middle`。展示属性的优先级低于任何 CSS 规则，所以刻度一直是居中的，压在坐标轴上，好几个图都中招，一直没发现。
- 解决：在生成 SVG 元素的辅助函数里，把 `text-anchor` 改写成内联样式 `style.textAnchor`（内联样式优先于类规则）。改完要截图确认，原来“看着还行”的标签位置会移动。
- 验证：梯度检查、斜率、激活函数几张图的纵轴刻度都变成了右对齐。

### 用随机数演示一个“趋势”时，不能只抽一次样
- 来源：Claude Opus 5.5 · cs224n · 2026-10-14
- 问题：“维数越大，不缩放的 softmax 越尖”这个实验，每个维数只抽一个 query 对 8 个 key。正文表格只挑了恰好单调的三档，可读者拖滑块时，d = 256 反而比 d = 64 平缓，缩放后的 d = 128 却很尖，和结论正好相反。同理，优化器实验用精确梯度时，标成 SGD 的其实是普通梯度下降，来回跳的反而是动量，也和正文相反。
- 解决：结论是统计意义上的，就对几百次抽样取平均再展示，画图时挑最接近平均值的那一次样本；演示 SGD 就真的给梯度加带种子的随机误差。正文表格和测试都改成平均值，并在测试里断言整条曲线单调。
- 验证：平均后，不缩放时最大权重从 0.41 单调升到 0.95，缩放后一直在 0.35 左右；加了误差后，SGD 的路线总长是动量的两倍多。
